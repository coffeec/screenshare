# 📺 网页版屏幕共享 (Go + Pion SFU)

基于 WebRTC 与 Golang (Pion) 构建的**极低延迟、高画质**的屏幕共享直播间。
纯浏览器体验，无需安装任何客户端！完美支持 1080P@60FPS 满血电竞画质，专为 APEX 开黑、游戏观战、远程代码评审打造。

---

## ✨ 核心特性 (Features)

- ⚡ **极致低延迟**：基于 Pion SFU 架构，服务器仅转发 RTP 数据流而不转码，浏览器与服务器直接对话，天然无 Glare。
- 🎯 **按需订阅 (Selective Subscription)**：观众席彻底分层！服务器拦截视频流，仅向主动点击“加入观看”的玩家下发视频。百人挂机 **0 带宽消耗**！
- 👀 **反向“偷窥”雷达**：主播专属体验，实时透视“当前有谁正在偷偷看你的屏幕”。
- 🎭 **APEX 专属化名**：加入大厅自动分配带有地理位置的 APEX 风格随机昵称（如 `广东的红甲恶灵`）。
- 🎮 **电竞级硬核控制**：支持动态切换硬编解码器（H.264 电竞模式 / VP9 观影模式），以及多档排位级码率（黄金/钻石/猎杀）。
- 🔒 **隐私与安全**：支持多房间隔离（`?room=<房间号>`）以及房间通行口令（Token）鉴权。

## 🚀 部署指南 (Deployment)

### 1. 生成自签证书 (服务器端执行一次)

`getDisplayMedia` 强依赖 Secure Context，必须使用 HTTPS。

```bash
cd ~/share && bash deploy/gen-cert.sh <你的节点域名或公网IP>
```

### 2. 编译与一键部署 (开发机执行)

```bash
# 下载依赖
GOPROXY=https://goproxy.cn,direct go mod download
```

在 Windows PowerShell 下直接运行一键部署脚本：
```powershell
.\deploy\build-deploy.ps1
```
> **原理**：交叉编译为 Linux 静态单二进制文件 → SCP 推送至服务器 → `pkill` 触发 Systemd 自动重启（实现免 Sudo 热更新）。

### 3. 安装 Systemd 服务守护 (服务器端执行一次)

编辑 `deploy/screenshare.service`，替换其中的 `CHANGE_ME` (鉴权 Token) 和 `CHANGE_TO_SAKURA_NODE_HOSTNAME`。
随后执行：

```bash
sudo cp ~/share/deploy/screenshare.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now screenshare
```

### 4. 内网穿透配置 (SakuraFrp 推荐)

需要建立**两条**隧道：

| 隧道类型 | 本地IP与端口 | 远程端口 | 用途说明 |
| :--- | :--- | :--- | :--- |
| **TCP** | `192.168.5.4:8443` | 任意分配 | 处理 HTTPS 页面访问与 WebSocket 信令 |
| **UDP** | `192.168.5.4:42000` | **必须保持 42000** | 承载所有的 WebRTC 核心音视频媒体流 |

> ⚠️ **注意**: UDP 隧道的远程端口**必须**与本地端口完全一致。因为 Pion 的 `SetNAT1To1IPs` 策略仅重写候选 IP 而不改写端口。建议选择同省节点（如广东电信选华南节点）以获得极致低延迟。

## 🎮 使用说明

- **局域网访问**: `https://192.168.5.4:8443`
- **外网穿透访问**: `https://<节点域名>:<TCP远程端口>`

*(注：自签证书首次访问请点击浏览器提示的「高级 → 继续前往」，这不影响 WebRTC 媒体权限)*

⌨️ **极客快捷键**: 按下键盘的 `S` 键（或点击界面底部的统计图标），可唤出硬核统计面板。实时监控当前视频分辨率、帧率、吞吐量以及硬件编码器状态（如果 `enc` 字段显示为软编如 OpenH264，说明硬件加速未生效，高画质下可能会掉帧）。

## 📈 带宽消耗 (极致省流策略)

**得益于革命性的按需订阅机制，未点击观看的潜水观众完全不消耗任何视频带宽。**
每个**外网订阅者**消耗 1×当前码率（局域网观众走内网，不占穿透流量）。整体系统瓶颈取决于你的家用宽带上行与内网穿透套餐的限速。

- 🏖️ **潜水模式**: 100 个人在房间大厅挂机聊天，如果没人点观看，总带宽消耗 = **0**。
- 🎯 **单人围观**: 1 人发车 + 1 个外网水友围观 = 1×码率 (猎杀档 8Mbps 即消耗 8Mbps)
- ⚔️ **大乱斗模式**: 4 人全部开启共享并互相观看所有人 = 每人消耗 3×下行 + 1×上行 = 满载运作

> *遇到 `limit: bandwidth` 提示说明当前网络带宽已经跑满，建议在 UI 下方将画质下调至“黄金路线”。系统底层自带 TWCC 反压兜底机制，网络超载时会自动降低画质，坚决不崩溃。*

## ⚠️ 已知限制与最佳实践

- **Linux Wayland**: 部分桌面合成器存在 30fps 的硬限制，建议只共享单个窗口而非整个桌面。
- **macOS**: 必须在系统设置中授予浏览器“屏幕录制”权限，并且苹果系统级限制仅能采集浏览器标签页的声音，无法采集全局系统声音。
- **断线重连**: 屏幕共享在断网恢复后无法自动重连（浏览器的安全机制要求 `getDisplayMedia` 必须由用户真实点击触发），需根据提示重新点击「共享屏幕」。
- **浏览器推荐**: 强烈建议所有用户使用 **Chrome** 或 **Edge**，它们对 H.264 硬件编码的底层支持最为完美。

## 🔮 进阶玩法 (可选)
如果觉得浏览器每次提示“不安全证书”太烦人：
花几块钱买个便宜的域名，CNAME 解析到你的内网穿透节点。然后用 `acme.sh --issue --dns` 签发一张免费的 Let's Encrypt 证书。只需要在启动参数里替换掉 `-cert` 和 `-key` 的路径，无需改动任何一行代码，即可享受纯净的绿锁 HTTPS 体验！
